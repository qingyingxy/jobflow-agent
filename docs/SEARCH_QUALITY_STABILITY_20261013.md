# 搜索准确性与稳定性修复（2026-10-13）

目标是保留完整用户要求、基于职责筛选岗位、控制一次更新的耗时，并自动继续未完成工作。搜索仍然是筛选产品，个人学历/专业资格分析保持独立。

## 实现

1. **完整意图与有效条件**：方向保存原文限定，例如“大模型应用开发”“数据分析”“测试平台开发”，相邻词组成的“大模型算法”不拆成两个任选方向。仅消除单独的“开发/研发”等职业后缀。方向、地点、届别、关键词、排除项随目标版本一起传入搜索与重筛。新增可选数组 `preferred_roles`，未命中偏好不会排除；它用于召回和有职责证据时的优先排序。未知表达仍可交给已有的、有原文校验的语义解析，失败保留待核实条件。
2. **条件编辑一致性**：传入结构化条件时，本地筛选、职责判断和模型证据校验使用同一份条件生成的查询。旧输入不覆盖用户修改。仅当旧目标的来源记录明确是本地解析、旧别名与原文完整方向可对应、没有正在执行的运行时，自动恢复限定并增加版本；不覆盖手工修改或模型解析结果。
3. **职责证据与三态**：关键词只出现在标题或任职要求中，不再直接通过。明确的本地职责证据可通过；需要理解职责含义时由模型引用原文段落复核。模型失败、超时或没有足够证据时保留待核实。短而明确的职责可以证明符合；证明不符仍要求完整职责。更新判定版本以使旧缓存失效。
4. **统一时限**：搜索、启动阶段、网页核验、方向复核和队列收尾共享 `web_search_budget_seconds` 截止时间。单条上限和收尾上限进一步约束剩余时间，不再增加第二段总预算。取消后保存已得到的正文和线索；浏览器释放、数据库写入和 API 轮询仍有少量收尾开销，不承诺硬实时。
5. **来源失败隔离与队列容量**：同一来源连续3次操作失败后，本轮暂缓该来源剩余链接。岗位明确不符或已关闭不计作来源故障。候选待处理队列最多120条；暂缓事件有明确原因和链接，持久化线索保留。下一次更新重置本轮失败计数。
6. **自动恢复与缓存**：更新同一目标版本时，最多取16条历史未完成具体岗位链接自动续验，按最新观察去重，优先处理较早未更新的链接；已核验、关闭、忽略、其他用户/目标版本的观察不复活。最多8个过期或方向复核未完成的已存岗位进入原有核验队列。当前用户7天内已核验且开放的官网正文可以复用，不重置核验时间；新官网接口正文到达时优先处理新证据。方向缓存仍绑定完整查询、正文、标题、URL与判定版本。
7. **交叉职责复核**：本轮新查询暴露出模型把销售中的一般分析工作当作数据分析岗位的问题。方向复核更新为 `job-role-review-v18-professional-work-scope`，要求判断实际工作对象、行动和专业交付，区分明确的交叉工作与借用一般技能。没有新增职位ID、公司名称或某条查询的例外；标题不同不直接排除。提示词改进仍不保证所有歧义都被模型识别。

这些规则不按单个企业、职位 ID 或测试查询特判。现有本地职责快捷判定仍对软件方向覆盖更充分，其他复杂职责由语义复核处理。缓存使用7天时效，与岗位库现有策略一致，并不保证7天内岗位绝不变化。

自动更新仍受既有页面定时器约束：页面打开且在前台才执行；没有新增关闭页面后的后台调度。

## 验证口径

- 新增 `tests/test_search_quality_stability.py`：完整方向、必选/优先、标题及任职要求不能证明职责、模型引用、手改条件、总时限、失败来源隔离、队列容量、恢复去重、历史升级、缓存归属及时效。合成样例检验代码契约，不作为模型准确率。
- 真实复测使用 `datasets/search_quality_retest_cases_20261013.json`：原4种查询，加广州前端、成都数据分析2种新查询；第一组重复一次，区分旧库响应与新增岗位时间。
- 每个冷启动案例使用空的临时 SQLite、真实搜索及模型服务、公开 JD，不发送用户简历，不投递。运行期间冻结应用代码并保存哈希。
- 继续报告首条经正文复审确认的可用岗位耗时、总耗时、实际页面前10条有效比例、明确可判断的已排除样本中误排除比例；同时列出未核实数量、模型失败及来源情况。最后一项不是全网漏召回率。
- 标签来自助手逐条复审正文，不能称为独立人工金标。未核实链接留在展示分母中；不足10条单独报告，不把少量正确结果包装成完整覆盖。

### 尚未解决的边界

- 跨职能工作的职责范围仍可能被模型判断得过宽；不能把所有模型通过项当作人工已确认。后续需要独立人工标注的新查询与跨行业职责样本。
- 搜索来源仍不均衡。首批岗位覆盖字节、小米、MiniMax、蔚来、京东等，但本轮所有组的页面前10条均来自字节跳动。缺少目标岗位时仍会尝试很多不相关页面。
- 杭州、成都均触及总预算，排队最长约137秒和144秒；失败来源隔离与统一时限改善可控性，未解决所有长尾延迟。
- 需要登录、人工确认或官网来源未确认的线索，不在本次明确的自动续验状态列表内；重新发现可能重试。7天缓存不保证期间岗位始终开放。
- 关闭页面后的常驻后台更新尚未实现。
