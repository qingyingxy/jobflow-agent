# 功能补齐与验收 · 2026-10-16

本轮补齐已识别的日常使用缺口：简历发送前确认、个人 JD 纠错、手动登记投递、账户数据管理、后台定时搜索，以及搜索展示与收尾等待。未重新进行真实网络搜索质量或模型准确率评测。

## 使用入口

| 功能 | 入口和行为 |
| --- | --- |
| 简历隐私 | 简历管理 → 上传并预览。本地隐藏常见姓名、邮箱、手机、地址、证件号和链接；核对实际文字并勾选后解析。可删去遗漏的个人信息；服务端不允许在预览中新增内容。 |
| 暂不解析 | 选择“仅保存文件，不解析”。之后可在已有版本点击“核对并解析经历”。同一确认文本复用缓存；解析失败保留文件和已有经历。 |
| JD 纠错 | 已分析岗位 → 纠正岗位条件。修改原文引用、名称、类型、必须/优先、全部/任选/待核实，或增删条件；填原因后本地重新匹配。保留修订记录，可恢复模型结果。 |
| 投递登记 | 申请进度 → 已经在官网投递？记录一下。明确勾选后从准备中转为已投递，来源标注用户确认；不发送申请、不伪造回执。原有凭证核验流程仍记录为系统核验。 |
| 数据管理 | 简历资料 → 账户数据与隐私。导出 ZIP；输入“删除我的数据”后永久删除当前用户数据。其他用户数据保留。 |
| 定时更新 | 已保存求职目标 → 定期更新。关闭 / 30 分钟 / 60 分钟，默认关闭。使用已保存条件，不使用未保存草稿。 |

## 行为边界

- 自动脱敏是辅助规则，不能保证识别所有个人信息。预览显示实际待发送文本，编辑后需要重新勾选。原文件仍保存在非公开本地目录，账户导出会包含原文件。
- JD 修改是当前用户的覆盖层，不会修改共享模型结果。原文或当前解析变化、修订版本冲突时拒绝旧表单提交。条件必须有当前 JD 的逐字来源；保存后不运行语义模型，因此会重新给出保守的本地匹配结论。
- 已有类型化学历分支保留原解析，界面允许调整强度和关系；复杂学历、专业、届别事实的任意重建不在本次编辑器范围内。
- 后台任务需要后端进程持续运行。停止后端期间不执行；重启后从当前时间计算下一次，不连续追赶所有错过的周期。调度采用原子领取，同一目标已有运行时复用；错误在目标配置中显示。
- 规则搜索在现有轮次和总时限内最多追加一次未覆盖公司的查询，完整保留搜索约束。Agent 模式沿用其决策和数量停止规则。补搜不保证找到第二家公司；本次没有新的线上来源占比或耗时提升数据。
- 公司组默认显示前三条，用户可以展开其余岗位或“全部展开”。不会删除其余结果。达到有效岗位目标后，剩余核验最多等待 20 秒，且不突破原总预算；待核验链接保留供后续更新。
