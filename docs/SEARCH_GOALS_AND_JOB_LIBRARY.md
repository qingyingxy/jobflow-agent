# 求职目标与岗位库

本次接入正式前后端的一条链路：描述需求 → 保存求职目标 → 展示已有岗位 → 搜索与核验 → 按当前目标筛选 → 收藏或忽略 → 更新同一目标。

## 输入与保存

- 首页的主要入口是自然语言，首次不预填固定的岗位或城市。点击“搜索并筛选”会自动整理并保存条件，无需逐项确认。
- “整理 / 修改条件”是可选入口；岗位方向和城市允许任意输入，多项用逗号或顿号分隔。“保存并筛选已有岗位”不启动新搜索。
- 必须地点限制结果，优先地点只影响排序。关键词与优先关键词分别保存，优先关键词未命中不降低资格状态。排除地点、排除岗位方向、招聘类型、届别和其他要求分别保存。
- 常见输入通过本地解析；有未识别的中文意图且配置了真实结构化模型时，最多用一次、8秒、无传输重试的模型调用补充地点或方向。输出必须绑定用户输入原文，本地排除条件保留。失败或未理解的条件保留为待核实，不要求用户重新填写全部信息。
- 没有简历也能使用。输入未提及届别时，可以从唯一的最高教育记录中读取有依据的毕业年份，标注来源。明确输入和结构化修改优先；“不限届别”不会被个人资料覆盖。
- 目标保存在 `search_goals`，浏览器只记住最近选择的目标。再次搜索直接复用已保存条件，不再调用需求解析模型。两个页面同时修改时按条件版本检查，过期写入返回409。

## 搜索与筛选

- 每次运行保存目标ID、条件版本、结构化条件快照和更新前的岗位事实快照。修改当前目标不修改旧运行条件。
- 匹配器直接接收结构化条件快照；生成的带标签查询用于搜索和方向模型复核。旧接口的自由文本查询仍支持本地解析。
- 原有搜索选择器、并行正文核验、独立方向复核、核验等待、自动补搜和预算限制继续工作。重复启动同一目标、同一版本的运行会复用进行中的执行。
- 岗位库复用当前用户已经保存的正式岗位；按当前目标重新计算三态结果：符合已知条件、待核实、明确不符。个人资格分析按需执行。
- 查询地点与岗位地点来自同一套城市词表。正文中服务客户的城市不充当工作地点。显式输入的其他城市也能作为结构化地点条件。
- 开放状态未知、正文未核验或核验超过7天的岗位保留为待核实。更新搜索时最多将8个有链接、待更新且没有明确冲突的旧岗位放进原有核验队列，仍受同一轮预算约束。
- 岗位库总数与本轮正文核验、待核验链接分别展示。进度和更新基线只使用当前条件版本的运行；修改条件后保留并重新筛选正式岗位，不显示旧条件的进度，也不把已有岗位误标为本轮新增。已关闭数量是明确不符数量的子集。
- 普通岗位列表默认隐藏明确不符和已关闭岗位，可以主动展开。收藏夹和已忽略列表保留用户选择，即使岗位不符合当前目标也可查看。
- 保留原有岗位去重、正文变化使旧分析失效和用户收藏/忽略状态继承能力。新增、正文变更、关闭按最近一次目标搜索开始前的事实快照展示。

## 自动更新的当前边界

目标面板可选择每30分钟或每小时更新，默认手动。当前定时器只在页面打开、处于前台、没有未保存修改且没有搜索正在进行时启动。关闭页面后不会继续后台搜索；没有引入常驻服务器调度器。最终投递仍由用户授权。

计时只在用户、目标、条件版本或频率变化时重新设置，普通页面刷新、搜索进度刷新和回调函数变化不会重置。打开条件编辑不算修改；比较实际条件和公司集合决定是否暂停，撤回修改后恢复。暂停时不会补发积压的更新请求。

## 接口与迁移

- `POST /api/discovery/goals/interpret`：可选的条件整理。
- `GET /api/discovery/goals`、`POST /api/discovery/goals`、`PATCH /api/discovery/goals/{id}`：保存和复用目标。
- `GET /api/discovery/goals/{id}/library`：当前目标下的岗位库、判断依据和变更。
- `POST /api/discovery/goals/{id}/search`：复用目标启动一次有预算的搜索，提交 `expected_version`。
