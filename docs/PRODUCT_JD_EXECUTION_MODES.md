# JD 解析调用优化与阶段恢复

手动解析、手动分析以及搜索后的自动分析统一通过 `src/services/analysis_runtime.py` 使用 `ProductJDExecutionParser`。默认仍为两阶段；单次调用作为显式可选模式。两个模式共用教育校验、原文引用校验、编译和本地资格判断。

普通能力匹配单独由 `EVIDENCE_MATCHING_MODE` 控制，默认 `local` 不调用匹配模型。显式启用 `semantic` 后，每个有普通要求且有经历证据的岗位另加一次批量匹配调用；有效缓存命中时为零次。以下表格只统计 **JD 解析**，不包含搜索、简历抽取和可选的能力匹配。

## 配置和调用次数

```dotenv
PRODUCT_PARSE_MODE=two_stage
PRODUCT_PROMPT_VERSION=product-jd-two-stage-v11
PRODUCT_SINGLE_CALL_PROMPT_VERSION=product-jd-single-call-v3-inline
PRODUCT_PARSER_VERSION=product-jd-parser-v9
```

将 `PRODUCT_PARSE_MODE` 改成 `single_call` 并重启后端即可切换。运行版本统一追加 `-execution-v3`，单次再追加 `-single-call`；即使本地 `.env` 固定旧版本标签，旧结果缓存也不会复用到新实现。模式默认仍为两阶段。

| 路径 | 正常模型调用次数 |
| --- | ---: |
| 两阶段首次解析，有要求 | 2 |
| 两阶段首次解析，无要求 | 1 |
| 两阶段第一阶段已保存，重试第二阶段 | 1 |
| 单次模式首次解析 | 1 |
| 完整解析缓存命中 | 0 |

每个模型阶段默认最多一次校验修复。单次模式的条件错误只请求修复指定条件，保留已校验的事实、原文条件和其余关系；抽取或根结构错误才重发完整请求。仍无自动切换执行模式。这里统计 `client.generate` 的逻辑调用；生产客户端内部的 HTTP 重试可能产生额外请求。实际成本应看 provider 的用量/账单，不能将调用次数等同于 token 或费用。

## 两阶段恢复

第一阶段抽取并通过本地校验后，立即把 `checkpoint` 写入本次 `AgentRun.validation_result` 并提交数据库，然后才调用第二阶段。快照包含抽取结果、身份指纹、原始阶段诊断和来源运行 ID。

第二阶段失败仍返回错误，不创建部分 `JobParseResult`，不输出成功匹配结论。下次用户重试解析或分析时，服务查找相同用户、岗位、正文、模型和版本的快照，重新校验后仅执行第二阶段。取消任务或进程中断也能保留已经提交的快照；它不会触发后台自动重试。

指纹包含实际抽取提示、Schema、输出上限、模型、provider、endpoint、推理配置和版本。正文、契约或模型配置变化，以及损坏的快照，都不会被复用。密钥不写入快照。查找范围为当前用户匹配的最近 50 次运行；找不到有效快照就重新抽取。

快照使用既有 JSON 字段，无需新迁移。`AgentRun.output` 仍只保存完整成功结果；沿用既有状态枚举，未完成运行不会被标记为 succeeded。恢复后的诊断只累计本次新调用，旧抽取用量保留在 `origin_attempts`，避免重复计算。此机制不提供并发请求合并或恰好一次执行保证。

## 单次模式

模型一次返回：

```json
{
  "facts": {},
  "requirements": [{
    "source_text": "计算机相关专业的硕士或博士",
    "level": "required",
    "relation": "any_of",
    "items": [],
    "reason": "硕士和博士为备选学历，共同要求计算机相关专业",
    "education": {
      "relation": "any_of",
      "branches": [
        {"source_text": "计算机相关专业的硕士或博士", "degree": {"operator": "eq", "level": "master", "source_text": "硕士"}, "major": {"mode": "related", "values": ["计算机"], "source_text": "计算机相关专业"}},
        {"source_text": "计算机相关专业的硕士或博士", "degree": {"operator": "eq", "level": "doctor", "source_text": "博士"}, "major": {"mode": "related", "values": ["计算机"], "source_text": "计算机相关专业"}}
      ]
    }
  }],
  "responsibilities": []
}
```

上例省略了默认的 scope/status 等字段；正式调用仍需按上下文确认 scope 并引用证据。每条条件内联关系和教育分支，本地生成索引并适配成既有抽取/关系结果，不再要求模型维护两份条件列表。仍可读取已保存的旧 `extraction`/`relations` 响应，便于零调用回放。

不同教育谓词允许引用同一完整句子，例如硕士、博士两分支共享专业限制。本地用不同的字段原文（硕士、博士）生成展示用 `items`，资格判断使用完整教育谓词；重复同一谓词不能充当两个分支。普通技能的 `any_of` 仍需至少两个不同原文选项。

本地逐条验证结构、原文、关系和教育条件，并汇总错误。抽取正确而某些条件错误时，补充请求只返回 `repaired_requirements`。必须恰好覆盖指定索引，不得修改条件原文或强度、删除条件或修改其他条件；合并后再次执行完整校验和编译。修复耗尽仍返回失败，不发布部分成功结果。单次的有效内容保留用于本次局部修复，没有新增跨请求的单次检查点。

使用独立的单次提示词，完整 Schema 同时写入 system 消息，兼容当前 `json_object` 接口。学历英文别名要求单词边界，避免 RoboMaster 被当作 master。当前毕业状态需要明确已毕业证据，未来届别不等于当前已毕业。开放专业范围和不能表达的日期区间保留为 unknown/unresolved，不能收窄后给出通过结论。

对于独立的简单全局届别，教育分支若原样重复同一个年份和引用，本地去掉分支上的重复字段，全局约束继续绑定申请学历。对于仅含届别和学历的原文，若同一年份已完整保存在必需的教育条件中，编译时去掉重复全局门槛。地域、复杂日期及其他不支持的限定不会通过这一步被删除。

两个模式仍然只能验证结构和证据约束，无法仅靠 JSON 合法性证明模型理解正确。因此模式选择需要独立核对关系、范围和最终资格结果。
