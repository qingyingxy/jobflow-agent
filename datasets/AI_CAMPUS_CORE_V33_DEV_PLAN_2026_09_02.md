# AI Campus Core Parser v33 development plan

- Parser: `jd-core-parser-v33`
- Prompt: `jd-core-parser-prompt-v22`
- Schema: `core-job-fields-v9`
- Skill ontology: `skill-ontology-v4`
- API status: one authorized run completed; no retries or replay

## Rationale

V32 returned two valid predictions from three public non-blind development
cases. One case reached the 240-second outer timeout. The two successful cases
still exposed a false `any_of` group for ordinary framework examples and weak
recall for directly required analysis, diagnosis, and optimization abilities.
V32 remains a recorded but rejected development result.

V33 changes the model boundary rather than adding case-specific prompt rules.
The caller splits the source JD into stable clauses, annotates their section,
and assigns `SCnnn` IDs. The model returns only source IDs and semantic clause
decisions. Local code resolves each ID back to exact source evidence and
continues to own skill normalization, ontology IDs, public fields, and
evidence construction.

## Deterministic constraints

- A slash by itself is ordinary enumeration and cannot justify `any_of`.
- `any_of` is retained only when the same source clause contains an explicit
  scoped choice such as “at least one”, “any one”, “choose”, “one of”, or a
  direct `A or B` separator.
- An unsupported model `any_of` is downgraded to ordinary conjunction before
  compilation. If the source names an upper category and concrete examples,
  the category remains required and the examples become mentions.
- Technical clauses in requirement and preferred sections are checked for
  coverage. An omitted clause produces an auditable warning. When Parser
  validation repair is enabled, exactly one targeted complete-output repair is
  allowed by the existing retry budget; the final result retains the warning
  if coverage is still incomplete.

These rules depend on source language and section scope, not dataset case IDs
or company-specific text.

## Offline verification

During implementation, the frozen non-blind dev-21 manifest was read only for
clause-indexing shape checks; no prediction was generated by that offline
check. Clause counts range from `14` to `41` per JD, with a mean of `23.43`.
Indexed source text retains `90.58%` of the raw text characters before adding
compact IDs and section labels. The response is smaller because it no longer
repeats evidence text for every semantic clause.

`campus-ai-015` now exposes separate requirement clauses for optimization
strategy, model-effect analysis, and training/data problem diagnosis. This is
an indexing observation only, not a scored model result.

## Authorized smoke result

The fixed smoke contains `campus-ai-023`, `campus-ai-027`,
`campus-ai-116`, `campus-ai-126`, and `campus-ai-142`. None appears in the v31
development selection or the v32 smoke. The generated five-case manifest has
no label-review findings, and all five local v33 request/schema checks passed.
The user authorized sending these five public JDs to DeepSeek once. They ran
serially with a 240-second model and outer case timeout; model retries and
Parser validation repairs were both zero. No resume, replay, or second call
was performed.

Only `campus-ai-142` produced a valid prediction. `campus-ai-023` and
`campus-ai-027` timed out. `campus-ai-116` and `campus-ai-126` returned JSON
that failed Schema v9 validation. The five-case success rate is therefore
`0.2000`. The all-case five-field Macro-F1 is `0.2195`, but it primarily
reflects four failed predictions and is not a clean semantic-quality result.

The successful-only diagnostic for `campus-ai-142` has a five-field Macro-F1
of `0.9167`, skill-concept F1 of `0.5825`, concept-strength Macro-F1 of
`0.8054`, qualifier F1 of `0.8000`, and false-group rate of `0.0000`. It is one
case and cannot be reported as overall Parser performance.

## Decision

V33 is not frozen. It misses the `1.0000` first-attempt success gate. Any
follow-up code or schema compatibility change must be versioned as v34 and
verified with offline or mocked cases before any newly authorized API smoke.
The five v33 cases must not be called again without fresh explicit
authorization. Blind-8 and the sealed holdout remain excluded from
development, replay, and tuning.

Proposed minimum gates are a `1.0000` first-attempt success rate, skill-concept
F1 of at least `0.7500`, concept-strength Macro-F1 of at least `0.7500`, and a
false-group rate no greater than `0.1000`. Blind-8 and the sealed holdout remain
excluded from development, replay, and tuning.
